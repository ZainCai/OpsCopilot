## 背景

语义模型 v1（W3）开始构建拓扑。拓扑的边与节点来自多种途径：

1. 数据源**直接观测**的事实（如 Prometheus 活跃 target、云 API 返回的资源实例）；
2. **同源规则推断**（如同一 scrape job 的 targets 归属同一服务）；
3. **跨源推断 / 时间近似 / 兜底猜测**（如按命名约定把两个节点关联起来）。

若把这三类混为一谈，因果推理（RCA）会建立在猜测之上：一个低质量推断边可以把故障根因"指"到毫无关系的节点上——**错误的 RCA 比没有 RCA 更糟**，因为它会消耗用户信任与 LLM 预算（ADR-002）。

## 决策

**拓扑证据分三级置信度，低置信度硬门禁，不进入因果推理。**

| 级别 | 语义 | 典型来源 | 因果推理 | 拓扑展示 |
| --- | --- | --- | --- | --- |
| `high` | 直接观测事实 | 连接器直接发现的资源节点；数据源显式声明的边 | ✅ 参与 | ✅ 展示 |
| `medium` | 同源规则推断 | 同一 job/同集群等单数据源内部规则聚合出的节点与边 | ✅ 参与 | ✅ 展示 |
| `low` | 跨源推断/兜底 | 命名约定匹配、时间近似关联、默认猜测 | ❌ **拒绝** | ✅ 展示（标注"推断"） |

具体规则：

1. **节点**：凡由连接器直接发现（Discover 产出）均为 `high`；由规则聚合出的虚拟节点（如"服务"节点）为 `medium`。
2. **边**：`high` 仅授予数据源显式声明的关系（如云 API 的依赖接口）；单源规则推断为 `medium`；跨源推断一律 `low`。
3. **硬门禁**：因果推理的输入图 = `CausalSubgraph()`，其中 `low` 级节点与边**一律剔除**；若某节点被剔除，以其为端点的边必须一并剔除（保持图一致性，不允许悬空边）。
4. **合并取高**：多来源发现同一实体时，节点置信度取最高档——有直接观测就不要降级为推断；来源（Source）保留最新观测者的标识。
5. 置信度取值与契约层 `pb.TopologyNode/TopologyEdge.Confidence`（string）直接兼容，取值即 `high`/`medium`/`low`。

## 理由

1. **可解释**：每条拓扑证据都能回答"这是观测到的还是猜的"，RCA 结论可审计；
2. **保守优先**：门禁只拦"猜的"，不拦"单源规则推断"——后者有明确规则可复查，先允许其进入，待运行数据表明 medium 误报率高再收紧（规则可演进，门禁本身不变）；
3. **架构级而非展示细节**：这一决策决定了因果引擎的输入契约与拓扑图的合并规则，属于语义模型的地基，故入 ADR。

## 后果

- 正面：RCA 输入质量有下界；低质量推断仍可在 UI 展示（标注），信息不丢失；
- 负面：纯靠推断的关联在早期 RCA 中"看不见"，可能漏掉一些真实根因——这是**用召回换精度**的有意取舍；
- 后续：需要 `CoverageReport`（覆盖率自检）持续输出低置信度占比，为"medium 是否收紧 / low 是否升级"提供数据依据；
- 撤销条件：运行数据表明 medium 的误报率显著高于收益（此时 medium 也应剔除），或出现了可靠的边置信度打分模型（此时可从离散分级升级为连续分值）。

## 交叉检查提醒

1. 本决策与 ADR-002 强耦合：因果推理是"算子前置"的第一环，**若门禁放开 low，等于把猜测喂给算子与 LLM，成本与正确性双输**。
2. 契约层 `TopologyNode` 当前**没有 Labels 字段**，而发现层 `ResourceNode` 有——映射时标签信息暂不进 pb 契约（W5 API 层如需展示，届时评估加字段或走旁路，**不要**把标签塞进 Confidence 等既有字段）。
3. `ValidFrom/ValidTo` 是 bi-temporal 时点查询（as_of，v2 C15）的基础：节点生成时必须写 `ValidFrom = 观测时间`，`ValidTo` 留空表示当前有效；**任何合并操作不得清空 ValidFrom**，否则历史时点拓扑不可重建。
