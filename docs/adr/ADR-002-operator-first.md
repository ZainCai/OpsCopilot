- 关联：ADR-003（LLM 单出口）、v1.0 选型、v1.3 成本约束

## 背景

成本硬约束：SaaS 单租户月成本（含 LLM token）必须控制在订阅价的 30% 以内，否则商业模式不成立。目标单次 RCA 成本 <¥1。

若直接把原始指标/日志喂给大模型，单次诊断 token 消耗将随监控规模线性膨胀，成本不可控；且大模型处理海量原始数据的稳定性差。

## 决策

**"算子前置、LLM 兜底"——数据分析由确定性算子先做，LLM 只做证据综合与排序。**

具体：
1. 异常检测、日志聚类、链路分析、变更回溯等由轻量 AI 算子完成（便宜、稳定、可解释）；
2. 算子压缩后的**证据摘要**才进入 LLM，单次 RCA 控制在 <50k token；
3. LLM 不解读原始数据，只输出"结论 + 证据引用 + 置信度"（见 ADR-003 的引用校验）；
4. 按次预算硬熔断（跨模块调用强制携带 Budget）。

## 理由

1. **成本**：算子成本是 LLM 的零头，且不受上下文长度影响；这是达成 <¥1/次 的唯一可行路径；
2. **正确性**：确定性算子不会幻觉，让 LLM 只做它擅长的"综合推理"，把幻觉面收窄到最小；
3. **架构级而非优化项**：这一决策同时决定了成本模型、prompt 设计与降级行为，因此写在 ADR 而非性能章节。

## 后果

- 正面：成本可控、结果可解释、幻觉面小；
- 负面：算子库需要持续建设（异常检测/聚类等算法能力是长期投入）；
- 撤销条件：模型成本下降两个数量级，或算子维护成本超过其节省的 token 成本。

## 交叉检查提醒

本决策与 ADR-003 的"引用校验"强耦合——**若允许 LLM 直接读取原始数据，成本与幻觉两项收益同时失效**。
