# ADR-017: 审计信任边界与身份钩子（一期现状声明 + 二期真身份收口）

- **状态**：**已接受（2026-09-14 按 round10 清单 P2-C4 收口；本期零产品代码，
  语义声明 + 二期升级路径）**
- **日期**：2026-09-14
- **关联**：ADR-005（审计分离）、ADR-009（listen 安全闸门）、round10 清单 P2-C4
  （`docs/reviews/round10-P2遗留-M3清单.md` #11）、
  `docs/设计-sessionstore消费方与接线.md`（拍板 §5.2 / §5.5）、ADR-014（RCA 最小链路）

## 背景（读事实）

三处"审计/身份"现状均为**显式拍板**，不是遗漏；本文档把它们收口为一条 ADR，
给二期真身份落地一个升级锚点。

1. **runbook 写面不入 incident_audit 哈希链**（`cmd/opscopilot/rest_runbook.go`
   runbookWriteGate / runbookTokenGate：写路径只过 Token 闸门 + store 接线，
   无审计写入）。语义：runbook 是操作手册（文档资产），不是事件处置动作；
   "谁改了手册"不构成"谁对事件做了什么"的审计事实，故不入事件审计哈希链。
2. **RCA 复盘会话轮次正文不入审计**（设计文档拍板 §5.2）：轮次正文落独立表
   `rca_session_turn`，incident_audit 哈希链不动、不追加 rca-review 动作；
   `llm_meta` 只存 SHA-256 / 长度 / 模型名（对齐 llm_summarizer.go 脱敏纪律）。
3. **actor / created_by 自报可冒充**：无用户身份体系，鉴权是 ADR-009 单 Token
   （共享密钥 + 常量时间比较）；REST body 里的 created_by / actor 字段为调用方
   自报（runbook 的 created_by / mounted_by、session 的 created_by /
   participants、RCA 手动触发的 actor 参数）。

## 决策

**本期（M3 阶段 2）**：三条现状**原样保留**，本文档即收口声明——哈希链的
完整性保证"改了什么不可抵赖"，**不保证"谁声称的不可冒充"**；单 Token 形态下
"谁"是弱信任维度，属一期已知边界（已拍板接受，见设计文档 §5.5）。

**二期（用户身份落地时，本文档升级点）**，按优先级：

1. **actor 服务端解析**：引入登录/JWT 后，所有 actor / created_by 由服务端
   从会话解析，body 自报字段降级为忽略或仅展示（不再当身份源）。
2. **incident 级权限**：session 是 incident 子资源，读会话/事件须过事件权限
   （设计文档 §5.5 已预留：表结构 participants / created_by 非空可查）。
3. **runbook 写面**：若事件域要求"手册变更留痕"，补 incident_audit
   action='runbook_write' 追加（不动哈希链结构）；若维持文档资产定位，本
   ADR 现状声明继续有效——二选一届时拍板。

## 风险

- **冒充面（本期已知）**：共享 Token 泄露 = 可冒充任意 actor 写审计可见的
  自报字段。缓解：Token 是 ADR-009 既有信任根，本期不新增攻击面（自报字段
  本就只作展示/留痕，不驱动任何权限判定）；哈希链对动作序列完整，冒充者
  无法篡改历史。
- **误读为缺陷**：三条现状常被当作"应入审计"的反例。本文档显式声明边界，
  避免后续轮次重复开项。

## 替代方案（否决理由）

- **A：本期引入用户身份**。否决于 M2/M3 范围纪律：会话/事件权限体系是跨域
  改造（含前端登录态），远超 round10 清单 P2 级范围；设计文档 §5.5 已明确
  "本期不做用户级授权，表结构预留"。
- **B：runbook / session 强行入哈希链**。否决：轮次正文体积大且非事件事实
  （拍板 §5.2 理由）；runbook 是文档资产，硬塞审计链稀释"事件处置"语义。

## 交叉检查提醒

- **ADR-005**：审计分离纪律不变——本 ADR 是"哪些动作构成审计事实"的边界
  声明，不改变 append-only / 哈希链实现。
- **ADR-009**：单 Token 是本文档"弱身份"的前提；二期若引身份体系，鉴权层
  升级走新 ADR（本文档不预设方案）。
- **排期**：round10 清单 P2-C4 至此闭环；二期池立项时把"身份/权限"作为独立
  评估件，本 ADR 状态届时改"已接受 → 已升级"。
