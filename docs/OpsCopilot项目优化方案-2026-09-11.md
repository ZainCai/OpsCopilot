| 维度 | 现状 | 评级 | 主要短板 |
|---|---|---|---|

## 三、实施顺序（4–5 人并行版，总计 ≈2 周）

```
D1–D2（四条线并行）：
  甲：#1 仓库清理(0.5d) → #3 Gate 锁内 IO(0.5d) → 认领 #6 内存有界化
  乙：#4 ChangeStore 持久化(1.5d，含 migration)
  丙+丁：#2 配置收敛一次做完(3d，含 #10 去全局/魔法数字、env 清单表)
  戊：#5 契约测试编写（只写测试锁死现状行为，不动重构）
D3–D5：
  丙+丁：#5 状态机抽取 + Mem/PG 双 store 迁移（戊写的契约测试兜底）
  乙：#8 ProcessAlerts 异步落库 → 转 #11①② 租约迁移+escalation 入 PG
  戊：#11③ 拓扑 Builder 归属方案 ADR（分片 vs 单 owner，先定案再动代码）
  甲：#9 后端巨型文件拆分（机械，编译即验证）→ 认领 #11④ leader 门禁
D6–D8：
  丙+丁+戊：#11 双实例同跑集成测试（faultinjector 回放+判决去重校验）+ 修复收尾
  全员：#7 压测（单实例基线 + 双实例扩展性两轮）+ 备份恢复演练 → 《容量基线》= M2 出口材料
  甲：#9 console 冻结 + 独立前端工程脚手架（不阻塞 M2 出口）
```

单人节奏约 4–5 周；4–5 人并行后压缩到 **约 2 周**（#11 升 P1 使总量 +3–4d），W11 仍留给 RCA（#12）。
排序依据不变：先零风险卫生项与单点并发修复，契约测试先于大重构；#11 放在 #4/#8 之后——持久化的变更库与异步落库就绪后，多副本语义才完整可测。

## 四、统一护栏

- 每项独立提交、独立可 revert；行为变更项（#2/#3/#5/#8/#11）必须带 ADR 或 CHANGELOG 条目。
- 重构前先补测试到"改坏能红"：#5 靠契约测试、#3/#8 靠现有 race CI + 新增慢渠道模拟。
- `OPS_*` 收敛期间维护一张 env 清单表（名称/默认值/消费方/非法值策略），最终由 config schema 生成。
- 不动 internal 禁互 import 边界；所有装配改动继续集中在 cmd/assembly.go。

## 附录：incident 双 store 漂移清单（#5 契约测试实测，重构时的输入）

| # | 点位 | 摘要 | 修复方向 |
|---|---|---|---|
| D1 | ack_by | PG 列**有写无读**，Get/Transition 永远返回空 | PG 侧确定性修复 |
| D2/D3 | Create 空 severity / createdBy | Mem 接受，PG NOT NULL 报错（DEFAULT 未生效路径） | PG 侧对齐或入口统一校验 |
| D4 | UpsertExternal 空 severity | PG 新建分支报错、**刷新分支反而能写空**（自相矛盾） | 随 D2 一并收敛 |
| D5 | source_meta | Mem 自由文本 vs PG JSONB 规范化/拒绝 | 定义 schema 统一 |
| D6 | Upsert 刷新返回值 | PG 不回填 ClusterKeys | PG 小修 |
| D7 | **MergeInto 簇转移** | **Mem 是 no-op**，违背自身注释与 PG 行为——嫌疑最大的真 bug | 以 PG 语义为准修 Mem |
| D8 | 人工单 ID 撞外部 `origin:ref` | Mem 静默改写人工单；PG 重试 8 代后报错 | 统一 ID 空间规则 |
| D9 | 归档可见性 | Mem 永驻 vs PG retention 物理删（ADR-010 已知代价） | 文档化，契约测试锁现状 |
| D10 | List 排序无第二键 / ExternalActive 判据 | 同刻时间戳下 PG 排序不稳；Mem 只看当前代、PG 看任意代 | 加排序键（000010 索引顺带）|

**#5 重构建议起点**：D1/D2/D3/D4/D6 为 PG 侧小修；D7 是 Mem/注释/PG 三方矛盾，动状态机前先拍 D7 语义；其余随状态机抽取一并收敛。
