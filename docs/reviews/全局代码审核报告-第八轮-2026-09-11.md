## 四、不确定部分及理由

1. **C6 超时语义**：取决于部署是单 worker 还是多 worker。单 worker 下 store 写与批事务同进程顺序执行，语义冲突不触发；多 worker 才需要"按条失败计数"或"批外独立事务"。**建议先定部署形态再落地**。
2. **C1 TOCTOU**：单 worker 实际不触发；修复收益取决于多 worker 时间表。若多 worker 排期明确，应提前到第二梯队。
3. **C2 collation**：生产库是否 `C` 排序未定；若非 `C`，tiebreaker 需要显式 `COLLATE "C"` 保证字典序稳定。本地无法核验生产库配置。
4. **游标 HMAC**：读路径鉴权方案未定（W7 计划）。不加鉴权时 HMAC 无意义；加了之后才有必要。属第三梯队的前置依赖。
5. **依赖 CVE**：未运行 `govulncheck`（本机未安装/未配置），go-redis 等依赖的已知漏洞未实测。不影响本地 build/test，但上线前应补一次。
6. **Dockerfile 修复验证**：本机无 Docker（README W1 阻塞项），修复后无法实测 `docker build`；需在有 Docker 环境验证，或 CI 增加镜像构建步骤。
7. **FK 依赖核对**：000006 引入的 FK（如 tenant/incident 级联）在生产库是否实际落地未核验——迁移仅在本地执行过，上线前需对生产库做一次迁移校验。
