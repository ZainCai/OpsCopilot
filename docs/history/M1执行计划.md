## 二、M1 目标与出口标准

**目标**：接入层（Prometheus + 阿里云/AWS 连接器）+ 存储 + 告警簇展示跑通。

**出口标准（缺一不可）**：

1. 影子模式降噪准确率 **>85%**（在 ≥1 个真实环境验证）；
2. 拓扑自动发现覆盖率 **>70%**（v1.3 §6 新增）；
3. 告警链路端到端延迟 P95 <30s（实测，非假设）；
4. 单机版升级流程演练通过（版本化迁移 + 升级前自动备份）；
5. 备份恢复演练一次通过；
6. 容量模型三级估算完成，压测数据回写架构文档。

**变更关联接口（2026-09-09）**：
- `internal/topology/change.go`：`ChangeEvent`（ID/NodeKey/Type/Source/Author/Ref/Revision/Summary/OccurredAt/TenantID/Confidence）+ `ChangeStore` 进程内存储。关键设计：
  - Type 封闭集合（deploy/config_change/rollback），未知类型拒绝——类型是下游关联规则的分支依据；
  - Confidence 零值默认 **medium**（外部系统声明≠连接器直接观测，ADR-007），可显式给 high；
  - ID 幂等（重复 → `ErrDuplicateChange`，不覆盖原记录）；严格模式 `NewChangeStore(nodeCheck)` 拒绝关联不存在节点（`ErrNodeNotFound`）——防"变更关联到幽灵节点"的静默失败，nodeCheck 由编排层注入图查找，模块不反向依赖；
  - 查询原语：`ByNode` / `ByNodeWithin([from,to] 闭区间)` / `Within`（全局窗），按时间升序；返回值为拷贝（并发安全，测试锁定不泄漏内部指针）；
  - 哨兵错误 `errors.Is` 匹配：webhook 侧据此映射 HTTP 状态码（`ParseChangeType`/`ParseConfidence` 错误也补了根因哨兵包装）。

- 验证：ChangeStore 11 测试 + webhook 11 测试全过（含端到端"告警前 30 分钟窗口命中变更"用例）；gofmt / build / vet / 全量测试 / 模块边界检查通过。

**as_of 时点查询 + 云 API 发现器（2026-09-09）**：
- `internal/topology/as_of.go`：`Graph.AsOf(t)` 基于 bi-temporal 可见性（ValidFrom ≤ t 且 (ValidTo 零 或 t < ValidTo)，半开区间 [from,to)）重建历史时点拓扑；端点不可见的边剔除（悬空引用纪律与 AddEdge 一致）；可链式接 CausalSubgraph（测试锁定组合用法）。`ParseAsOf` 空=当前、非 RFC3339 拒绝不静默。`ToProtoAsOf` 填契约 `ResolvedAsOf` 回执字段。**已知局限如实记录在代码注释**：Builder 尚无"节点消失"淘汰机制，内存图上 as_of 只能答"t 时刻已知有哪些"，不能答"t 时刻已消失的"——持久层（时态表）落地后补全。
- `internal/connector/azure`：Azure ARM 只读发现器，与 Prometheus 并列的第二个数据源。零第三方 SDK（纯 net/http，M1 只需列表+分页）；凭证走 `pkg/readonly` 同一套只读闸门（构造期拒绝写权限凭证）；Secret 直接承载 ARM 令牌，令牌获取流程留给编排层（认证与发现分离）；nextLink 分页 + maxPages=100 死循环防御（**修了一个自己写出的 bug：超限原本静默退出返回假完整结果，改为显式报错——拓扑缺一截比发现失败更危险**）；响应体 32MiB 上限；Collect 显式返回 ErrUnsupported（指标要走 Azure Monitor，不静默假装支持）；Key 用 `azure://vm/<vmId>`（订阅内稳定 GUID，不随改名/迁移变化）；健康检查用最便宜的 GET 订阅探针，401/403 归为 degraded 而非 down。
- 验证：as_of 9 测试 + azure 11 测试全过（假 ARM 服务覆盖分页、死循环、401、坏 JSON、超大响应、健康降级）；真实 Azure 经 `//go:build integration` + 环境变量门控，手动触发不进 CI；全量门禁通过。
