## 一、P0 代码正确性

### P0-1 【已修复】`Host` 退避状态无锁访问 → 并发崩溃

- **原症状**：`retryAt`/`backoff` 两个 map 全程裸奔（`RunOnce` 读、`backoffFor` 写），并发驱动采集触发 `fatal error: concurrent map writes` —— **不可 recover，直接杀进程**。
- **修复**：抽为独立 `scheduler` 类型（`internal/connector/host.go`），自带 `sync.Mutex`，提供 `shouldSkip`/`fail`/`succeed` 三个方法，所有访问统一加锁。
  - **刻意不复用 `h.mu`**：`RunOnce` 遍历中会调用 `HealthCheck/Collect/Discover` 等外部慢 IO，若与注册共用一把锁，一次慢采集会连带阻塞 `Register/Get/List`。注册表锁与调度锁职责分离、互不阻塞。
  - 顺带修掉一个隐患：原 `backoffFor` 在 `maxBackoff==0`（零值 Host）时会把退避时长封顶成 0 导致退避失效，现加 `max > 0` 保护。
- **回归测试**（此前必崩，现连跑 5 轮全绿）：
  - `TestHost_RunOnce_ConcurrentSafe`：8 goroutine × 200 次并发 `RunOnce`，配合 1ns 退避窗口放大写入频率。
  - `TestHost_ConcurrentRegisterAndCollect`：验证采集不阻塞注册/查询。
- **附带修复 `RunOnce` 返回值语义**（原恒为 nil、属误导性 API）：现仅当 **ctx 已取消**时返回错误；**单个连接器失败不中断本轮、不体现在返回值**（只记录日志并退避），以此保证"断连不丢任务"。该契约已写入注释，并由 `TestHost_RunOnce_CanceledContext`、`TestHost_Run_StopsOnCancel` 锁定。

### P0-2 【已修复】`rawAlert` 的 `status` 类型冲突

`Status`(结构体) 与 `StatusText`(字符串) 同享 `json:"status"`，标准解码遇旧版字符串形态即失败并导致**整批告警解析失败**。已改为 `json.RawMessage` 兜住两种形态再分支解析，`TestCollect_OldStatusFormat` 锁定回归。

## 二、P1 需求实现完整度

### 2.1 【已修复】指标采集缺失 → 配置化 PromQL

- 原状：`MetricSample` 全仓仅在定义处出现，`CollectResult.Metrics` 无任何写入（"纸面类型"）。
- 修复：新增 `Config.Queries []Query{Name, Expr}`，`Collect` 逐条执行 `/api/v1/query` 并归一化为 `MetricSample`（含时间戳、标签、`__name__` 回退）。
- **零配置默认关闭**：未配 `Queries` 则不采集指标且**不报错**，完全向后兼容 W2 早期只采告警的行为，可一行回退。
- 测试：`TestCollect_Metrics`、`TestCollect_MetricsFallbackName`。
- 已知限制：为严守"只读"可审计性，查询用 **GET** 而非 POST，超长 PromQL 可能受 URL 长度限制（已在代码注释中说明）。

### 2.2 【已修复】`Since`/`Scope` 静默忽略 → 显式 `ErrUnsupported`

新增 `connector.ErrUnsupported`。`Collect` 收到非零 `Since` 或非空 `Scope` 时明确返回包装后的该错误（`errors.Is` 可判），**不再静默按全量处理**——避免调用方误以为过滤生效。测试：`TestCollect_UnsupportedOptions`。

### 2.3 【已修复】只读闸门与连接器断开（含架构方案修正）

- 原状：`internal/connector` 对 `credential` **零 import**，ADR-002 只存在于注释；`Config.Token` 是裸字符串，传读写 token 也照单全收。
- **架构修正**：直接 import 会违反 P1-2 模块纪律（`internal/` 一级子目录 = 独立模块，跨模块须走 gRPC），CI 的 `check_module_boundaries.py` 会直接判红。故新建共享契约包 **`pkg/readonly`**（`pkg/` 定位正是"被 ≥2 个模块复用"）：
  - 定义 `Credential`、三个 sentinel 错误（`ErrNotReadOnly`/`ErrExpired`/`ErrEmptyID`）、`Expired()`、`Validate()`、`NewBearer()`；
  - `internal/credential` 用 `type Credential = readonly.Credential` **类型别名**复用，`Put` 改调 `readonly.Validate`；
  - `internal/connector/prometheus` 的 `Config` 增加 `Credential *readonly.Credential`，`New()` 中强制校验（非只读/空 ID/已过期一律拒绝构造），校验通过后自动取 `Secret` 作为 Bearer Token。
- 效果：**写权限凭证现在无法进入采集链路**，纪律从注释固化为编译期可校验的代码。
- 测试：`TestNew_ReadOnlyCredentialEnforced`、`TestCredential_SharesReadOnlyContract`、`pkg/readonly` 全覆盖（`Validate` 5 个分支 + `Expired` 3 个边界）。

## 七、第二轮复审：残余风险修复（2026-09-09）

针对 §五 残余清单中**可修复**的项逐条处理，并额外发现一个此前漏网的精度缺陷。

| # | 问题 | 修复 |
| - | - | - |
| 1 | **指标时间戳亚秒精度丢失（本轮新发现）** | `time.Unix(int64(tsSec), 0)` 把浮点秒截断为整秒，丢弃小数部分（实测丢 500ms）。改为 `time.Unix(0, int64(tsSec*1e9))` 纳秒换算，保留数据源完整精度。此前两轮均未识别，是逐行复查 `normalizeSample` 时发现的 |
| 2 | 超长 PromQL 受 URL 长度限制 | 编码后超过 `maxQueryURLLen`(1800B) 自动降级为 POST form。Prometheus 官方对 `/api/v1/query` 同时支持 GET/POST，POST 仅传递查询参数、**不改变服务端状态**，仍属只读查询（只读的判定标准是"不产生写操作"而非 HTTP 方法）。同时把响应体限流抽为 `readLimited`，供 GET/POST 共用，消除重复实现 |
| 3 | 单条查询失败吞掉全部指标 | 改为 `errors.Join` 聚合所有失败并**保留已成功的部分指标**一并返回——显式报错而非静默忽略，同时不再因一条查询失败连累其余指标 |
| 4 | 零值 `Host{}` panic | `ensureSched()` 惰性初始化调度状态；`Register` 惰性建 map（避免写 nil map）；`Run` 对 `interval<=0` 兜底（**取局部值而非回写字段**，避免多 goroutine 并发 Run 的数据竞争） |

### 变异验证：证明测试有效，而非空转

测试通过 ≠ 测试有效。对新增的两项修复做反向验证（故意改回缺陷版本，确认测试会失败）：

| 变异 | 测试结果 | 结论 |
| - | - | - |
| 时间戳改回 `time.Unix(int64(tsSec), 0)` | **FAIL**：`diff=-500ms`（正是被丢弃的亚秒） | 测试确实捕获截断缺陷 |
| POST 阈值调至 1000000（即永不降级） | **FAIL**：`should fall back to POST, got GET` | 测试确实捕获降级缺失 |

两项变异后均已恢复正确实现并复测通过。
